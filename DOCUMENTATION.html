Wstęp

Dynamiczny rozwój technologiczny i rosnąca złożoność rynku komputerów biurkowych sprawiają, że wybór odpowiedniego sprzętu staje się coraz bardziej wyzwaniem dla zwykłych użytkowników. Obecne na rynku rozwiązania pozwalają jedynie na przeglądanie katalogów czy porównywanie wyspecjalizowanych parametrów technicznych, lecz nie uwzględniają personalizowanych preferencji użytkownika ani nie poprzedzają wyboru inteligentnym doradztwem [1]. Praca niniejsza opisuje opracowaną platformę DreamDesk – system webowy łączący katalog peryferyjnych urządzeń komputerowych z zaawansowanymi funkcjami porównywania oraz doradztwem opartym na sztucznej inteligencji generatywnej [2]. Rozwiązanie pozwala użytkownikom na bezproblemowe budowanie spersonalizowanych konfiguracji komputerów biurkowych oraz uzyskanie rekomendacji opartych na ich konkretnych potrzebach. W poniższej pracy omówiono architekturę techniczną systemu, zastosowane technologie oraz wyniki przeprowadzonych testów funkcjonalnych.

Cel i zakres pracy

Głównym celem pracy jest opracowanie i wdrożenie platformy webowej DreamDesk, która umożliwi użytkownikom intuitywne porównywanie peryferyjnych urządzeń komputerowych oraz budowanie spersonalizowanych konfiguracji przy wsparciu systemu rekomendacyjnego opartego na sztucznej inteligencji. Platforma powinna zapewniać wygodny interfejs użytkownika, bezpieczne przechowywanie danych oraz komunikację z zaawansowanymi modelami AI.

Zakres pracy obejmuje następujące obszary: W Rozdziale 1 – Wprowadzenie opisano obecny stan rynku komputerów biurkowych, przeanalizowano istniejące rozwiązania konkurencyjne oraz uzasadniono potrzebę opracowanego systemu. W Rozdziale 2 – Implementacja przedstawiono szczegółową architekturę aplikacji, opisano stosowane technologie frontend (React, Tailwind CSS), backend (Next.js), bazę danych (PostgreSQL z Prisma ORM) oraz integrację z modelami AI (Google Generative AI, Groq SDK). W Rozdziale 3 – Testy zaprezentowano metodologię testowania, opisano przeprowadzone testy funkcjonalne komponentów, integracji z API oraz omówiono uzyskane wyniki. Ostatni rozdział, Rozdział 4 – Podsumowanie, zawiera refleksję nad ukończonym projektem, omówienie osiągniętych celów oraz propozycje możliwych rozszerzeń systemu w przyszłości.

1 - Wprowadzenie

Rynek urządzeń peryferyjnych do komputerów biurkowych stanowi segment który wymaga od konsumentów posiadania wiedzy technicznej w celu dokonania optymalnego wyboru. Monitory, klawiatury, myszki, głośniki oraz inne peryferium różnią się znacznie pod względem parametrów, ceny, zastosowania i kompatybilności. Niniejszy rozdział omawia bieżącą sytuację na rynku, przegląda istniejące rozwiązania oraz uzasadnia potrzebę opracowania platformy DreamDesk.

1.1 Rynek komputerów biurkowych i jego wyzwania

Komputer biurkowy to złożony system składający się z podzespołów oraz peryferyjnych urządzeń wejścia-wyjścia. O ile dobór procesora, karty graficznej czy pamięci RAM jest stosunkowo standaryzowany, tak dobór peryferyjnych urządzeń (monitora, klawiatury, myszy, głośników) zależy w dużej mierze od indywidualnych preferencji użytkownika oraz specyfiki jego pracy [1]. Współczesni użytkownicy – zarówno programiści, projektanci graficzni, gracze, jak i pracownicy biurowi – mają zróżnicowane wymagania względem ergonomii, koloru, opóźnienia, odświeżania czy precyzji [2].

Głównym wyzwaniem jest przejrzenie wielkiej liczby dostępnych na rynku produktów, porównanie ich specyfikacji oraz wybranie optymalnego zestawu odpowiadającego indywidualnym potrzebom. Większość istniejących rozwiązań oferuje jedynie katalog produktów bez inteligentnego wsparcia w procesie decyzyjnym.

1.2 Istniejące rozwiązania analogiczne

Na rynku dostępne są różne kategorie narzędzi wspierających wybór komputerów i peryferyjnych urządzeń:

  • Serwisy e-commerce takie jak Amazon, Newegg czy polskie sklepy oferują katalogi produktów z możliwością filtrowania i sortowania, jednak bez personalizacji doradztwem czy porównywaniem tych samych produktów w kontekście potrzeb użytkownika [3].
  • Specjalistyczne portale recenzenta takie jak TechRadar czy Tom's Hardware publikują szczegółowe testy porównawcze, ale wymagają manualnego przeszukiwania i czytania długich artykułów.
  • Narzędzia konfiguratora PC takie jak PCPartPicker pozwalają na budowanie kompletnych zestawów, jednak skupiają się na podzespołach (CPU, GPU, RAM) a nie na peryferyjnych urządzeniach [4].
  • Aplikacje mobilne sklepów oferują wygodny dostęp do katalogów, ale brakuje im zaawansowanych funkcji porównywania czy rekomendacji.

Brak rozwiązania integrującego katalog peryferyjnych urządzeń z zaawansowanym systemem rekomendacyjnym opartym na sztucznej inteligencji stanowi istotną lukę na rynku.

1.3 Potrzeba systemu rekomendacyjnego

Współczesne modele sztucznej inteligencji generatywnej, takie jak GPT czy Gemini, pozwalają na stworzenie inteligentnego doradcy, który w naturalny sposób interpretuje preferencje użytkownika i na ich podstawie rekomenduje najbardziej odpowiadające mu rozwiązania [5]. Tego typu system może analizować tekstowe opisy preferencji, porównywać specyficzne cechy produktów oraz dostarczać spersonalizowanych rad opartych na kontekście użytkownika. Integracja takich narzędzi z aplikacją webową umożliwia stworzenie nowoczesnego, przyjaznego dla użytkownika doświadczenia (user experience) przy wyborze peryferyjnych urządzeń komputerowych.

2 – Implementacja

Niniejszy rozdział opisuje szczegółową architekturę techniczną platformy DreamDesk. Omówiono zastosowane technologie, strukturę systemu oraz proces wdrażania poszczególnych komponentów. Platformę zbudowano w architekturze klient-serwer z wykorzystaniem nowoczesnych frameworków webowych oraz bazy danych relacyjnej.

2.1 Architektura aplikacji

DreamDesk zbudowano w oparciu o architekturę Full Stack JavaScript/TypeScript wykorzystującą:

  • Frontend: React 18.3.1 z TypeScript – nowoczesne komponenty interaktywne z stylowaniem Tailwind CSS
  • Backend: Next.js 14.2.18 z App Router – serverless API routes do obsługi logiki biznesowej
  • Baza danych: PostgreSQL na platformie Supabase – bezpieczne przechowywanie danych użytkowników i katalogów produktów
  • ORM: Prisma 5.22.0 – mapowanie obiektowo-relacyjne dla ułatwienia pracy z bazą danych
  • Autentykacja: NextAuth 4.24.10 – bezpieczne zarządzanie sesjami użytkowników z obsługą OAuth
  • AI Integration: Google Generative AI 0.24.1 oraz Groq SDK 1.1.2 – zaawansowane modele dla generacji rekomendacji

2.2 Frontend - React i Tailwind CSS

Interfejs użytkownika zRealizowano przy użyciu React z biblioteki komponentów typu funkcyjnego. Tailwind CSS zapewnia szybkie stylowanie za pomocą utility classes, co przyspiesza proces rozwoju i ułatwia utrzymanie konsystentnego designu na całej platformie. Główne komponenty obejmują:

  • Header.tsx – nawigacja i wyświetlanie danych bieżącego użytkownika z avatarem
  • CatalogPage.tsx – przeglądanie katalogów produktów z filtrowaniem i wyszukiwaniem
  • CompareView.tsx – wizualna porównania wybranych produktów (szczególnie dla myszy biurkowych)
  • Configurator.tsx – budowanie spersonalizowanych zestawów peryferyjnych
  • AIChat.tsx – conversational interface do rozmowy z AI doradcą
  • ProfilePage.tsx – profil użytkownika z zapisanymi konfiguracjami i możliwością uploadowania avatara

Aplikacja korzysta z Context API do zarządzania stanem globalnym (AppContext, SetupContext) oraz Framer Motion (wersja 12.38.0) do dodania animacji przejść.

2.3 Backend - Next.js i API routes

Backend aplikacji zimplementowano jako serię API routes w Next.js 14, które udostępniają następujące endpointy:

Ścieżka API Metoda HTTP Opis
/api/auth/[...nextauth] GET, POST Obsługa autentykacji NextAuth (logowanie, rejestracja, Google OAuth)
/api/chat POST Wysyłanie wiadomości do AI doradcy i odbieranie rekomendacji
/api/setups GET, POST Pobranie i zapisanie konfiguracji użytkownika
/api/user/avatar POST Upload i przechowywanie avatara użytkownika

Każdy endpoint obsługuje autentykację poprzez sesje użytkownika i zwraca dane w formacie JSON.

2.4 Baza danych - PostgreSQL i Prisma

Dane aplikacji przechowywane są w PostgreSQL na platformie Supabase, która udostępnia hostowany serwer bazy danych z automatycznym backupem i skalowalnością. Schemat bazy danych zdefiniowany jest za pomocą Prisma Schema i obejmuje następujące główne modele:

  • User: id, email, name, image (avatar w base64), createdAt – dane dotyczące użytkownika platformy
  • Account: powiązania użytkownika z dostawcami OAuth (Google) – wymagane przez NextAuth
  • Session: sesje zalogowanych użytkowników – wymagane przez NextAuth
  • Product: id, name, type, specs (JSON), price – produkty z katalogu
  • Category: id, name – kategorie produktów (monitory, klawiatury, myszy itp.)
  • Setup: id, userId, name, components (JSON), createdAt – zapisane konfiguracje użytkownika

Migracje bazy danych zarządzane są komendą npx prisma db push, która synchronizuje schemat z serwerem bazy danych.

2.5 Integracja AI - Google Generative AI i Groq

Inteligentne rekomendacje generowane są za pomocą dwóch zaawansowanych modeli AI:

  • Google Generative AI (Gemini): Główny model wykorzystywany do generacji conversational responses w komponencie AIChat. Model otrzymuje kontekst preferencji użytkownika oraz katalog dostępnych produktów i generuje spersonalizowane rekomendacje [6].
  • Groq SDK: Model ultra-szybki wykorzystywany do szybkich zapytań oraz wstępnej analizy preferencji użytkownika. Groq zapewnia niskie opóźnienia i wysoki throughput [7].

Komunikacja z modelami odbywa się poprzez REST API z użyciem klucze API przechowywanych w zmiennych środowiskowych (.env file). Wygenerowane odpowiedzi cachowane są w celu redukcji kosztów API oraz poprawy wydajności.

2.6 Autentykacja i sesje użytkowników

Autentykacja zaimplementowana jest za pomocą NextAuth 4.24.10 z dwoma dostawcami:

  • Google OAuth 2.0: Umożliwia szybkie logowanie przy użyciu konta Google. Wymaga konfiguracji GOOGLE_CLIENT_ID i GOOGLE_CLIENT_SECRET w zmiennych środowiskowych [8].
  • Credentials Provider: Tradycyjne logowanie e-mail/hasło z haszowaniem haseł bibliotieką bcryptjs. Nowe konta można rejestrować poprzez formularz rejestracji.

Sesje przechowywane są w bazie danych (database session strategy), co gwarantuje ich persistencję między sesjami przeglądarki. Konfiguracja NextAuth znajduje się w pliku src/lib/auth.ts.

3 – Testy i wyniki

Testowanie aplikacji DreamDesk obejmowało zarówno testy jednostkowe komponentów React, testy integracyjne API routes oraz testy funkcjonalne całego systemu. Niniejszy rozdział opisuje przyjętą metodologię testowania oraz uzyskane wyniki.

3.1 Testowanie funkcjonalności komponentów

Poszczególne komponenty React przetestowano pod kątem poprawności renderowania oraz responsywności interfejsu. Testowane komponenty obejmowały:

  • Header.tsx: Weryfikacja wyświetlania informacji użytkownika, poprawne formatowanie nazwy, wyświetlanie avatara z fallback na ikonę. Testy przeprowadzono dla stanów zalogowany/niezalogowany.
  • CatalogPage.tsx: Test filtowania produktów po kategorii, wyszukiwanie po nazwie, sortowanie po cenie. Wszystkie funkcje zadziałały poprawnie.
  • CompareView.tsx: Porównanie wybranych myszy biurkowych (ze względu na dostępne dane w katalogu) z wizualizacją parametrów takich jak DPI, typ połączenia, cena. Test wykazał poprawne grupowanie i prezentację danych.
  • Configurator.tsx: Dodanie i usunięcie produktów z konfiguracji, zapis do localStorage. Funkcjonalność działała bez błędów.
  • ProfilePage.tsx: Test formularza logowania/rejestracji, upload avatara, wyświetlanie zapisanych konfiguracji. Wszystkie funkcje działały prawidłowo.

3.2 Testowanie integracji z API

Endpointy API przetestowano przy użyciu narzędzi takich jak Postman oraz bezpośredniego wywoływania za pomocą fetch API z frontendu:

  • /api/chat: Test wysyłania zapytania do AI doradcy z różnymi preferencjami użytkownika (np. "potrzebuję myszy dla graczy" vs "szukam myszy do pracy biurowej"). Modele zwróciły logiczne i stosowne rekomendacje.
  • /api/setups: Test pobierania konfiguracji zalogowanego użytkownika – dane prawidłowo pobierano z bazy danych. Test zapisu nowej konfiguracji – dane poprawnie zapisywały się do bazy.
  • /api/user/avatar: Test uploadu pliku obrazu (JPEG, PNG) – konwersja do base64 zadziałała, zapis w bazie danych przebiegł poprawnie. Test fallback'u na brak avatara – wyświetlana ikona zamiast braku obrazu.
  • /api/auth/[...nextauth]: Test logowania za pomocą Google OAuth – poprawna redirekcja do Google, kod autoryzacyjny prawidłowo obsługiwany, sesja zapamiętywana w bazie danych. Test tradycyjnego logowania – haszowanie hasła działa prawidłowo, sesje utrzymywane między odświeżeniami.

3.3 Wyniki i obserwacje

Przeprowadzone testy wykazały, że:

  • Stabilność aplikacji: Aplikacja działa bez krytycznych błędów. Interfejs jest responsywny zarówno na komputerach stacjonarnych jak i na urządzeniach mobilnych.
  • Wydajność AI: Modele Gemini i Groq generują rekomendacje w rozsądnym czasie (2-5 sekund w zależności od złożoności zapytania). Cachowanie wyników przyspiesza powtórzonych zapytań.
  • Bezpieczeństwo autentykacji: Sesje są prawidłowo zarządzane, haszowanie haseł funkcjonuje bezpiecznie, OAuth integracja nie ujawnia poufnych danych użytkownika.
  • Integracja bazy danych: Prisma ORM prawidłowo mapuje dane, nie odnotowano błędów na poziomie dostępu do bazy. Migracje schematu przebiegły bez problemów.
  • Ograniczenia katalogu: Obecny katalog zawiera ograniczoną liczbę produktów (głównie myszy). Pełne wdrożenie wymagałoby rozbudowy bazy danych o więcej kategorii i produktów.

Ogółem, wdrażane rozwiązanie spełnia założone cele funkcjonalne i stanowi solidną bazę do dalszego rozwoju.

4 – Podsumowanie

Niniejsza praca opisała opracowaną i wdrożoną platformę DreamDesk – system webowy łączący katalog peryferyjnych urządzeń komputerowych z zaawansowanymi funkcjami porównywania oraz doradztwem opartym na sztucznej inteligencji generatywnej. Projekt stanowi odpowiedź na identyfikowaną lukę na rynku, gdzie brakuje rozwiązania integrującego przyjazny interfejs użytkownika z inteligentnymi rekomendacjami.

Główne osiągnięcia projektu obejmują:

  • Opracowanie pełnego stosu aplikacji webowej (Full Stack) w architekturze klient-serwer,
  • Bezpieczną autentykację użytkowników z obsługą OAuth i tradycyjnych kont,
  • Integrację z zaawansowanymi modelami AI (Google Gemini i Groq) dla generacji spersonalizowanych rekomendacji,
  • Intuicyjny interfejs użytkownika umożliwiający porównywanie produktów i budowanie konfiguracji,
  • Zaawansowane zarządzanie sesją i przechowywanie preferencji użytkownika w bazie danych.

Wdrożona platforma w pełni spełnia założone cele funkcjonalne oraz stanowi solidną bazę do dalszego rozwoju. Perspektywy na przyszłość obejmują:

  • Rozbudowa katalogu produktów: Dodanie większej liczby kategorii peryferyjnych urządzeń oraz rozszerzenie bazy produktów.
  • Rozszerzenie funkcjonalności AI: Implementacja uczenia maszynowego (machine learning) do personalizacji rekomendacji na podstawie historii preferencji użytkownika.
  • Optymalizacja wydajności: Wdrożenie zaawansowanych technik caching'u, CDN do dystrybucji medów oraz optymalizacja zapytań do bazy danych.
  • Mobilna aplikacja: Stworzenie natywne aplikacji mobilnej na platformy iOS i Android używając React Native.
  • Integracja z e-commerce: Nawiązanie partnerstwa ze sklepami online w celu umożliwienia bezpośredniego zamawiania produktów z platformy.
  • Analityka i raportowanie: Dodanie panelu administracyjnego z analizą zachowań użytkowników i statystykami popularności produktów.

Praca na DreamDesk dostarczyła cennych doświadczeń w zakresie full-stack development'u, integracji API zewnętrznych oraz architektury systemów webowych. Projekt demonstruje możliwości jakie oferuje nowoczesna kombinacja React, Next.js, PostgreSQL oraz zaawansowanych modeli sztucznej inteligencji dla tworzenia innowacyjnych aplikacji internetowych.

5. Установка и запуск

5.1 Требования

  • Node.js 18+ и npm 9+
  • PostgreSQL 14+ (рекомендуется Supabase)
  • Git для клонирования репозитория

5.2 Пошаговая установка

Шаг 1: Клонирование

git clone https://github.com/repo/dreamdesk.git
cd dreamdesk
npm install

Шаг 2: Конфигурация БД

Создать PostgreSQL БД в Supabase и получить Connection String

Шаг 3: Google OAuth

В Google Cloud Console создать OAuth 2.0 credentials и получить CLIENT_ID и CLIENT_SECRET

Шаг 4: .env файл

NEXTAUTH_URL=http://localhost:3000
NEXTAUTH_SECRET=generate-random-string
GOOGLE_CLIENT_ID=your-id
GOOGLE_CLIENT_SECRET=your-secret
DATABASE_URL=postgresql://...
DIRECT_URL=postgresql://...
GROQ_API_KEY=your-key

Шаг 5: Инициализация БД

npx prisma db push
npm run db:seed  # optional

Шаг 6: Запуск

npm run dev

Приложение будет доступно на http://localhost:3000

9. Безопасность

9.1 Аутентификация

  • Google OAuth 2.0: Безопасная авторизация через Google
  • Credentials Provider: Email/Password с хешированием
  • Session Management: NextAuth + Prisma Adapter
  • CSRF Protection: Встроенная в NextAuth

9.2 Шифрование пароля

Пароли хешируются с помощью bcryptjs с 10 солью:

const hashedPassword = await bcrypt.hash(password, 10);
const isValid = await bcrypt.compare(inputPassword, hashedPassword);

9.3 Валидация входных данных

  • Server-side валидация всех API запросов
  • Проверка типов данных через Prisma schema
  • Санитизация входных данных

9.4 Авторизация

  • Проверка сессии в API routes через getServerSession
  • Проверка владельца ресурса перед доступом
  • Изоляция данных между пользователями

9.5 Переменные окружения

  • Все секреты хранятся в .env
  • .env файл в .gitignore (не коммитится)
  • На продакшене переменные хранятся в Vercel Secrets
